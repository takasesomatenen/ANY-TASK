# ゲームバランス — 実測と調整の記録

ルールは勘で決めていません。エンジン（`src/engine.mjs`）の各ルールをフラグ化し、
αβ探索AIどうしの自己対戦（`src/sweep.mjs` / `src/balance.mjs`）で
**先手勝率・引き分け率・平均手数・決着理由の内訳**を測りながら詰めました。

再現方法:

```bash
node src/balance.mjs 200 4 0.15   # 現行ルールを 200局・探索深さ4 で測定
node src/sweep.mjs   60  3        # ルール24通りの総当たり
```

`temperature` は AI が最善手からどれだけ逸れるかの幅です。
0 に近いほど強く、決定的に指します。

---

## 設計目標

| 指標 | 目標 |
|---|---|
| 先手勝率 | 50% 付近 |
| 引き分け率 | 低い（千日手で逃げられない） |
| 平均手数 | 15〜40手（構想が立つ長さ） |
| 決着理由 | 撃破・侵攻・判定がどれも実際に出る |

---

## 潰した問題 3つ

### 問題1：合体駒どうしが噛み合わず、59% が千日手

初版は「合体駒は単体では取れない」「合体駒は合体駒を取れない」でした。
結果、終盤は必ず **塔 vs 塔の膠着**になり、盤上で何も起こらなくなりました。

```
body2 range2 --- inv:none    先手 78.6%  引分 53.3%  平均 32.8手
```

**対策**：合体駒どうしの捕獲を解禁（`stackCapturesStack`）。
互いに相手の塔を取れるので、塔は「無敵の要塞」ではなく
「置き場所を間違えたら即死する主力」になりました。

### 問題2：侵攻勝ちを合体駒に許すと、先手が100%勝つ

「BRAIN が敵陣最奥に到達したら勝ち」を素直に入れると、
合体駒が2マス滑って **8手で盤を渡り切り**、先手が勝つだけのゲームになりました。

```
body2 range2 --- inv:any     先手100.0%  引分 0.0%  平均 8.4手
body3 range2 --- inv:any     先手 91.7%  引分 0.0%  平均 8.6手
```

**対策**：`invasion: "lone"` — **単体の BRAIN でしか侵攻勝ちできない**。
乗り込むには必ず合体を解かねばならず、その瞬間から BRAIN は誰にでも取られます。
速度が落ち、リスクが釣り合いました。

### 問題3：千日手が「逃げ得」になっていた

引き分けを残すと、不利な側が塔を振って千日手に持ち込めてしまいます。

**対策**：千日手・手数切れは **判定**（`judge()`）で決着させる。
侵攻度 → BODY 数 の順で比較し、後手に **コミ 0.5**。
これで引き分けは **全条件で 0%** になりました。

## 先手有利をどう消したか

問題1〜3を潰した時点で、低ノイズ・探索深さ4での先手勝率は **76.7%** でした。
補正案を4つ実装して比較（180局、深さ4、temp 0.15）:

| 補正 | 先手勝率 | 引分 | 平均手数 |
|---|---|---|---|
| なし | 76.7% | 0.0% | 21.0手 |
| コミ 1 | 70.6% | 20.6% | 21.0手 |
| コミ 2 | 56.1% | 0.0% | 21.0手 |
| **初手税（先手の初手は BODY 移動のみ）** | **53.3%** | **0.0%** | **23.1手** |
| 初手税 ＋ コミ1 | 43.2% | 17.8% | 23.1手 |
| 後手が最初から合体済み | 33.3% | 0.0% | 21.0手 |
| 後手合体済み ＋ 初手税 | 0.0% | 0.0% | 7.9手 |

コミだけでは足りません（コミは千日手局の裁定しか動かせず、
戦術的な決着は先手が取り続けるため）。
**初手税**が最も素直に効き、しかも引き分けを増やしませんでした。

採用：**初手税 ＋ コミ 0.5**。

## 現行ルールの実測値

`DEFAULT_RULES`（BODY3 / 合体駒2マス / 塔は塔を取れる / 侵攻は単体BRAINのみ /
初手税あり / コミ0.5）、各200局:

| 探索深さ | temp 0.06 | temp 0.15 | temp 0.30 | 平均手数 |
|---|---|---|---|---|
| 3 | 71.5% | 81.5% | 63.5% | 19〜23手 |
| 4 | **48.5%** | **53.0%** | 64.5% | 21〜23手 |
| 5 | 80.0% | 46.5% | 52.0% | 25〜32手 |
| 6 | 22.0% | 20.0% | — | 22〜26手 |

**引き分けは全条件で 0.0%。** 決着理由も撃破・侵攻・判定が毎回混ざります。

### この表の正直な読み方

先手勝率が探索深さで **22%〜81% まで振れています**。
これは「先手が有利」でも「後手が有利」でもなく、
**このゲームが鋭く、読みの深さが結果を支配する**ことを意味します。
深さ3では先手に、深さ6では後手に振れており、**偏りの向きが一貫していません**。
補正前に見られた「どの条件でも先手が勝つ」という一貫した偏りは消えています。

したがって「先手勝率 ≒ 50%」と言い切れるのは、
**同程度の読みの深さで戦う場合**に限られます。

### 読みの深さが結果を支配する（＝運ゲーではない）

探索深さに差をつけた対戦（各80局、temp 0.15）:

| 対戦 | 強い側の勝率 |
|---|---|
| BLUE 深さ4 vs RED 深さ2 | 70.0% |
| BLUE 深さ2 vs RED 深さ4 | 88.8% |
| BLUE 深さ5 vs RED 深さ3 | 88.8% |
| BLUE 深さ3 vs RED 深さ5 | 83.8% |
| BLUE 深さ6 vs RED 深さ4 | 60.0% |
| BLUE 深さ4 vs RED 深さ6 | 83.8% |

**手番の色に関係なく、深く読める側が勝ちます。** 先後の差より実力差の方がずっと大きい、
というのが拮抗性の実質的な担保になっています。

## 真剣勝負にはスワップ（ピー・ルール）を

先手勝率が探索深さで振れる以上、「初手税＋コミで完全に均衡した」と主張するのは誠実ではありません。
**後手が、先手の初手を見てから陣営を入れ替えられる**スワップを併用すれば、
先手有利・後手有利のどちらであっても構造的に消えます
（Hex や TwixT で標準的に使われている方法です）。

先手は「奪われても構わない、ちょうど互角の初手」を選ぶしかなくなり、
初手選択そのものが読み合いになります。
`index.html` ではデフォルトで有効です。

## 調整に使えるつまみ

`src/engine.mjs` の `DEFAULT_RULES`。`src/sweep.mjs` が全通りを測ります。

| フラグ | 現行値 | 効果 |
|---|---|---|
| `bodies` | 3 | BODY の数。多いほど盤が詰まり、タックルが刺さりやすい |
| `stackRange` | 2 | 合体駒の滑走距離。上げるほど鋭く、短期決戦になる |
| `stackCapturesStack` | true | false にすると終盤が膠着し千日手が急増 |
| `tackle` | true | false にすると合体駒が実質無敵になる |
| `invasion` | `"lone"` | `"any"` は先手必勝、`"none"` は千日手が急増 |
| `komi` | 0.5 | 判定時の後手ボーナス。1以上にすると後手に振れすぎる |
| `openingTax` | true | 先手有利の主な打ち消し |
| `maxPly` | 60 | 手数切れ |
