# BODY N BRAIN

> 6×6・36マスの2人用アブストラクト。**コマにコマを乗せると、性質が変わる。**

**BODY**（■・縦横1マス）と **BRAIN**（●・斜め1マス）。
どちらも単体では鈍いのに、BRAIN が BODY の上に乗ると
**8方向に2マス滑る合体駒**という、どちらの単体にも無い動きに変わります。

そして合体駒は単体の駒では取れません。代わりに **タックル** —
BODY が体当たりして、上の BRAIN だけを叩き落とせます。
落ちた先が盤外なら、その BRAIN は撃墜されて負け。
**強くなるほど、負け筋も同じ駒に集まります。**

## 遊ぶ

```bash
node build.mjs        # index.html を生成（依存パッケージなし）
open index.html       # ブラウザで開くだけ
```

`index.html` は完全に自己完結した1ファイルです（サーバ不要・外部通信なし）。
初回は**7ステップの操作型チュートリアル**が立ち上がり、各ルールを自分で1手指して覚えます。
その後は AI対戦（3段階）と2人対戦が選べます。

UIは白黒のみ。**塗りつぶし＝先手（黒）、枠だけ＝後手（白）**で、色に頼らず駒を見分けます。

## バランス

盤サイズもルールも自己対戦で実測して決めました（詳細は [BALANCE.md](docs/BALANCE.md)）。

- 4×4 / 5×5 / 6×6 / 7×7 を比較。**大きければ良いわけではなく**、7×7 は決着の
  50〜88% が侵攻勝ちになる横断競走に化け、先手勝率も 1.7〜22% と壊れます。
  5×5 も AI を強くすると **11.7%** まで崩壊。→ 残るのは 4×4 と 6×6。
- **引き分けは全条件で 0.0%**、6×6 の平均は 50〜77手。
- **ただし、どの盤サイズでも先後の均衡は探索の深さに対して保証できません**
  （深さ3/4/5 で 4×4 は 48〜78%、6×6 は 24〜46%）。だからこそ
  **スワップ（ピー・ルール）** を既定ONにしています。盤サイズの選択は
  均衡の担保ではなく、**ゲームの手触りの選択**です。
- 6×6 を選んだのは数字ではなく設計上の理由 — 中央が広く合体駒が縁で即死しにくいので
  「合体するか」の判断が長く効き、最奥段6マスなので侵攻勝ちが現実的な脅しになります。
  純粋な均衡と決着の多様性を最優先するなら 4×4 に戻す価値があります
  （`makeRules({ size: 4 })`）。
- 深さ5 対 深さ3 では、**手番の色に関係なく深く読める側が 82〜96% 勝ちます**。

```bash
node src/balance.mjs 200 4 0.15   # 現行ルールを測る
node src/sweep.mjs   40  4 size   # 盤サイズ x 射程 x 侵攻難度
node src/sweep.mjs   40  4 rules  # メカニクスのフラグ総当たり
node src/test.mjs                 # ルールのテスト 47件
```

## 構成

```
build.mjs            src/ を index.html と埋め込み用 artifact.html に1ファイル化する
src/engine.mjs       ルール本体。盤サイズ含め、バランス要素は全て DEFAULT_RULES でフラグ化
src/ai.mjs           評価関数 ＋ αβ探索
src/ui.mjs           ブラウザUI ＋ 操作型チュートリアル
src/template.html    UIの外枠とスタイル（白黒・ライト/ダーク両対応）
src/balance.mjs      自己対戦の測定
src/sweep.mjs        盤サイズ／ルールの総当たり比較
src/test.mjs         ルールのテスト
```
